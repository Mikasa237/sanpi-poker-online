# 三皮牌局

单机模式可以双击 `index.html` 直接开始。联机模式需要启动房间服务。

## 快速玩法

1. 选择 4–7 人牌桌和三档 AI 难度。
2. 每人先下 10 底注，再收到一张暗牌和一张明牌。
3. 赖子不参与先手争夺，其余明牌最大者先下注；若明牌都是赖子，则由庄家下一位先手。按顺序选择下注、跟注、加注、全下或弃牌。
4. 第一轮结束后暗弃一张牌，存活玩家依次公开摸第三张牌。
5. 第二轮下注结束后开牌：普通牌比较点数和，三皮按等级与目标点数比较。
6. 两轮发牌完成、尚未轮到自己时可以提前弃牌；已经行动过则不能提前弃。
7. 第三张牌点数最大的非赖子玩家取得第二轮先手；花色只用于争夺先手，不参与最终结算。
8. 最终完全同分时当前底池不拆分，累计到下一手；下一手唯一总赢家获得当前底池和全部累计底池。

游戏进度、筹码、设置和累计战绩会自动保存在当前浏览器中。牌桌右上角可切换行动速度、声音与动画。

牌桌采用玩家第一视角：你的底牌、明牌和摸牌固定在近景手牌区，其他玩家的公开牌带有“明/摸”标记；大小王分别使用黑白与彩色 JOKER 插画，赖子使用独立 WILD 牌面。

筹码归零即淘汰，不会自动补充筹码。AI 破产后会退出当前牌桌；你的筹码归零时本局立即失败，可一键重新开局。

## 联机模式

在当前目录运行：

```powershell
npm install
npm start
```

然后访问 `http://localhost:3000/online.html`。创建房间后会得到固定链接，例如：

```text
http://localhost:3000/room/AB12CD
```

联机房间支持 2–10 个真人座位，不加入 AI。房主开始第一手后，其他玩家仍可进入旁观；下一手有空位时会按加入顺序补座。昵称可在房间内随时修改，同一房间不允许重名。

房主可在开局前设置底注（5–100，5 的倍数）和单注封顶（0 表示无上限，否则为本钱的 10 的倍数且不高于本钱）。底注同时作为最小下注和最小加注单位；单注封顶限制任何一次下注或加注的目标额度，不会阻止玩家为了跟注补足已封顶的额度。牌局进行中不能修改，新一局开始前可以重新设置。

房主还可以设置每人本钱（100–100000，100 的倍数，默认 1000）。本钱影响新牌局和补座玩家，单注封顶不能超过本钱。

联机版采用服务器权威状态：每位玩家只会收到自己的底牌，其他人的底牌和牌堆内容不会提前下发。房间保存在服务器内存中，服务重启后会清空。

### 联机互动功能

- 第一只手牌分暗牌、明牌和公开摸牌三个阶段逐张发出；关闭动画时直接显示结果。
- 自己的行动回合会显示明显浮层、桌面描边、提示音和手机震动。
- 手机端把自己的手牌固定在视觉中心，对手收进可展开抽屉，下注区保持在一屏内。
- 先手只看非赖子明牌；所有明牌均为赖子时由庄家下一位先手。
- 首次入房可选择内置头像，或上传 PNG、JPEG、WebP 图片。图片会在浏览器中裁成 256×256 后上传。
- PNG/APNG、空 MIME、`image/x-png` 等常见浏览器差异均有兼容处理。
- 右侧“牌力图”使用公开信息和自己的底牌估算所有活跃玩家的赢面，不会读取对手暗牌。
- “公共聊天”支持自由文字、快捷语和鸡蛋/番茄/鲜花投掷。快捷语会用浏览器中文语音朗读，自由文字不会自动朗读。
- 快捷语使用随游戏发布的本地“轻快牌友”语音包；发送者和接收者都会听到，鸡蛋、番茄和鲜花也有独立音效。
- 房主可以禁言、解除禁言、清空聊天及关闭/开启聊天。普通玩家可以在本机静音聊天声音。
- 聊天记录只保留当前房间最近 50 条，房间消失后不会保留；上传头像同样只保存在服务器内存中。
- 牌堆跨手复用；当剩余牌少于 `3 × 当前人数 + 1` 时才收回全部 94 张统一重洗。
- 第一轮出现加注时，剩余牌堆会真实重洗，并播放洗牌动画和音效后再发第三张牌。
- 筹码耗尽后成为 1–3 转回溯者并保留原座；发牌后可请求查看目标底牌，对方 10 秒内同意后生效。目标成为唯一赢家时可获得一半初始本钱并复活，最多复活三次。

### 永久房主入口

永久房主链接有效期十年，普通联机首页和房间邀请页不会显示该入口：

```text
https://固定域名/host#owner=<长期令牌>
```

保存该链接后，你无需再向开发者索取临时入口，也不需要保持本机开机。每次打开房主链接都能重新创建房间；朋友的房间邀请链接仍会针对每一桌重新生成。

维护用的 `POST /api/host-links` 需要设置 `HOST_ISSUE_SECRET` 环境变量，并通过 `x-host-issue-secret` 请求头提供密钥；没有凭证时接口返回 401。客户端不会生成或展示永久房主链接。

长期令牌不依赖数据库，Render 只要保持相同的 `SESSION_SECRET`，即使服务重启或重新部署，房主链接也仍然有效。当前活跃房间仍存储在内存中，服务器重启后需要重新开房。

Render 一键部署入口：

```text
https://render.com/deploy?repo=https://github.com/Mikasa237/sanpi-poker-online
```

主要联机接口：

- `POST /api/rooms`：创建房间
- `POST /api/rooms/:code/join`：加入或恢复房间
- `POST /api/host-links`：生成长期房主入口
- `POST /api/host/verify`：验证房主令牌
- `POST /api/profile/avatar`：使用房间令牌更新头像
- `GET /api/avatars/:id`：读取房间内存头像
- `GET /api/health`：部署健康检查
- `/ws`：联机认证、牌局操作、聊天、投掷和房主控制

### Render 部署

仓库根目录提供 `render.yaml`，Render 会使用 `outputs` 作为服务目录。部署时需要创建一个 Render Web Service，并配置：

- Build Command：`npm install`
- Start Command：`npm start`
- Health Check Path：`/api/health`
- `SESSION_SECRET`：Render Blueprint 会自动生成；手动创建服务时应配置随机长字符串

免费 Node 实例从休眠中唤醒后会丢失内存中的旧房间。

## 文件

- `index.html`：游戏入口和界面结构
- `styles.css`：牌桌、卡牌与响应式布局
- `engine.js`：牌组、下注、三皮评估、边池和 AI 逻辑
- `app.js`：界面渲染、交互、音效和本地存档
- `online.html`、`online.css`、`online.js`：联机大厅、房间与第一视角牌桌
- `server.js`：权威房间服务、HTTP API 和 WebSocket 协议
- `package.json`：Node 服务依赖与启动命令
- `assets/`：彩色 JOKER、黑白 JOKER 与赖子牌插画
